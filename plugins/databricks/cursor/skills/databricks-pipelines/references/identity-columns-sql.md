Identity columns in SQL Declarative Pipelines generate auto-incrementing `BIGINT` values that are unique within a streaming table. The headline use case is **dimensional modeling with Auto CDC** — the streaming table generates a surrogate key per row while an Auto CDC flow drives inserts, updates, and deletes from an upstream CDC source. Identity columns also work on plain append-only streaming tables (no CDC, no SCD).

The engine-level semantics (syntax, value uniqueness, concurrency, partitioning rules) are inherited from Delta — see the canonical [Delta identity columns reference](https://docs.databricks.com/aws/en/tables/features/generated-columns#identity). This guide layers Lakeflow SDP-specific behavior (Auto CDC pitfalls, `RESTORE` behavior, full-refresh behavior, OOO CDC behavior) on top.

**API Reference:**

**Column syntax (inside the streaming table's column list):**

```sql
<col_name> BIGINT GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY
  [ ( [ START WITH <start> ] [ INCREMENT BY <step> ] ) ]
```

- **`GENERATED ALWAYS AS IDENTITY`**: System always generates the value; user-supplied values for this column are rejected. Recommended default.
- **`GENERATED BY DEFAULT AS IDENTITY`**: System generates a value when the insert does not supply one; user-supplied values are accepted. Use this when you need to insert a sentinel row (e.g. `-1` for an "unknown" dimension member).
- **`START WITH <start>`**: Optional. First value. Default `1`.
- **`INCREMENT BY <step>`**: Optional. Increment. Default `1`. Cannot be `0`.

Values are unique within the table but **not contiguous** — Delta guarantees values of the form `start + k*step` but does NOT guarantee `k = 0, 1, 2, …` per row. There may be gaps.

**Common Patterns:**

**Pattern 1: Auto CDC SCD Type 1 dimension with a surrogate key (two-statement form)**

```sql
CREATE OR REFRESH STREAMING TABLE my_catalog.silver.users (
  user_sk BIGINT GENERATED ALWAYS AS IDENTITY,
  user_id STRING,
  name STRING,
  city STRING
);

CREATE FLOW users_flow AS AUTO CDC INTO my_catalog.silver.users
FROM STREAM(my_catalog.bronze.users_cdc)
KEYS (user_id)
APPLY AS DELETE WHEN operation = 'DELETE'
SEQUENCE BY sequenceNum
COLUMNS * EXCEPT (operation, sequenceNum)
STORED AS SCD TYPE 1;
```

`user_sk` is the surrogate key; `user_id` is the natural/business key used as the Auto CDC merge key. **They are different.** See "Identity is NOT a merge key" below.

**Pattern 2: Append-only streaming table with a surrogate key**

```sql
CREATE OR REFRESH STREAMING TABLE my_catalog.silver.events (
  event_sk BIGINT GENERATED ALWAYS AS IDENTITY,
  event_id STRING,
  payload STRING
)
AS SELECT event_id, payload FROM STREAM(my_catalog.bronze.events);
```

No `FLOW AUTO CDC`, no `KEYS`, no `STORED AS` — identity columns on a plain ingest streaming table.

**Identity is NOT a merge key:**

In an Auto CDC flow, `KEYS (...)` must list the **natural/business key** (`user_id`, `order_id`, etc.) — NOT the identity column (`user_sk`, `order_sk`, etc.). The identity column's value is generated locally inside this table and cannot match an upstream row, so it cannot serve as a deduplication key.

Wrong (fails):
```sql
CREATE FLOW users_flow AS AUTO CDC INTO my_catalog.silver.users
FROM STREAM(my_catalog.bronze.users_cdc)
KEYS (user_sk)             -- ❌ identity column
SEQUENCE BY sequenceNum;
```

Right:
```sql
CREATE FLOW users_flow AS AUTO CDC INTO my_catalog.silver.users
FROM STREAM(my_catalog.bronze.users_cdc)
KEYS (user_id)             -- ✅ natural business key
SEQUENCE BY sequenceNum;
```

**Auto CDC pitfalls (each fails the flow):**

- **Identity column in `KEYS (...)`** — listing the identity column as the Auto CDC merge key fails. Use the natural business key instead.
- **Identity column in `COLUMNS * EXCEPT (...)`** — explicitly excluding the identity column fails. Remove it from the EXCLUDE list.
- **Upstream source supplies a value for the identity column** — if the source row has a column matching the identity column's name, the flow fails. Alias or drop that column in the source view before the flow.

**Critical operational behavior:**

1. **Must be `BIGINT`.** Other integer widths and string types are not allowed for the identity column itself.
2. **Values are unique but not contiguous.** There may be gaps. Do not assume values are dense or in insertion order.
3. **No temporal ordering guarantee.** Identity values are NOT correlated with event timestamps, insertion order, or `SEQUENCE BY` column values.
4. **Concurrent transactions are not supported.** Declaring an identity column on a Delta table disables concurrent transactions on the target — concurrent writers conflict (typically surfaced as `DELTA_METADATA_CHANGED`). Use identity columns only when the workload tolerates serialized writes.
5. **Cannot partition by an identity column.** The identity column cannot appear in `PARTITIONED BY (...)` / `CLUSTER BY (...)` on the streaming table.
6. **Full refresh regenerates values.** A full refresh of the streaming table resets identity allocation; existing identity values are not preserved. Do not use identity values as stable cross-system references.
7. **Identity allocation is monotonic and non-reusable, even under `RESTORE`.** If the underlying Delta table is rewound, the identity high watermark does NOT rewind — re-materialized rows receive new identity values.
8. **Out-of-order CDC events may produce different identity values for the same logical row.** When a DELETE arrives before its corresponding INSERT for the same merge key, identity values are not preserved across the reconstructed row versions.

**NOT covered by this guide:**

The `GENERATED` keyword appears in three different column features. Do not conflate them:

| Feature | Syntax | Purpose |
|---|---|---|
| **Identity column** | `id BIGINT GENERATED ALWAYS AS IDENTITY` | Auto-incrementing surrogate key — this guide |
| **Generated column** | `day STRING GENERATED ALWAYS AS (date_format(ts, 'yyyy-MM-dd'))` | Value computed from other columns — see [Delta generated columns](https://docs.databricks.com/aws/en/tables/features/generated-columns) |
| **Default column** | `created_at TIMESTAMP DEFAULT current_timestamp()` | Static default when value is not supplied — see `streaming-table-sql.md` |

**KEY RULES:**

- Identity columns are supported on streaming tables. Do NOT say they are unsupported.
- Identity columns are NOT supported on materialized views. If the user asks for an auto-incrementing column on a MV, suggest converting to a streaming table or computing the surrogate key downstream.
- Always use `BIGINT` for the identity column.
- In Auto CDC, `KEYS (...)` must list the natural business key, never the identity column.
- Recommend `GENERATED ALWAYS AS IDENTITY` by default; use `GENERATED BY DEFAULT` only when the user needs to insert specific values (e.g. sentinel rows).
- Warn that values are unique but not contiguous, and that full refresh regenerates them.
